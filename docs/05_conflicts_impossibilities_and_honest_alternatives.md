# Phase 0 (e): Conflicts, Android OS Impossibilities & Honest Engineering Alternatives

Every conflict or non-root Android OS impossibility identified in the brief is listed below alongside the exact, honest alternative we implement.

---

## 1. Conflict / Impossibility Matrix

| # | Requirement / Brief Statement | Why It Collides With Android 12–17 OS Rules or Builder Limits | Honest Alternative Implemented in OmniVoice |
| :---: | :--- | :--- | :--- |
| **1** | **"Start the always-on microphone engine after a reboot (`BOOT_COMPLETED`)"** | On **Android 14–17 (`API 34–37`)**, calling `startForegroundService()` with `foregroundServiceType="microphone"` from a `BOOT_COMPLETED` broadcast receiver throws `ForegroundServiceStartNotAllowedException` / `SecurityException`. On **Android 12–13**, it starts silently with muted/zero audio. | **Two-Pronged Legitimate Architecture (Section 1 Rule):**<br>1. **Primary (`ROLE_ASSISTANT`)**: Onboarding guides you to set OmniVoice as the **Default Digital Assistant** (`OmniVoiceInteractionService` + `OmniRecognitionService`), which the OS itself binds at boot and grants background microphone privileges.<br>2. **Fallback (If `ROLE_ASSISTANT` is declined)**: `BootCompletedReceiver` never calls `startForegroundService()` for the mic; instead it posts a high-priority 1-tap **"Tap to Wake OmniVoice"** notification (and optional home-screen shortcut) that legally starts the microphone foreground service on tap. |
| **2** | **`android:isAccessibilityTool` vs. Android 17 `AdvancedProtectionManager`** | Earlier Android 13 guides suggested adding `android:isAccessibilityTool="true"` to bypass Restricted Settings. However, Google Play policy and **Android 17 (`API 37`) Advanced Protection Mode** reserve `isAccessibilityTool="true"` strictly for assistive apps for users with disabilities, and Advanced Protection forcibly disables non-exempt `AccessibilityService`s. | 1. We **remove `android:isAccessibilityTool="true"`** from `accessibility_service_config.xml` so the declaration is 100% truthful.<br>2. We detect Android 17 `AdvancedProtectionManager` state in `Android12To17Compat`. When Advanced Protection is ON, OmniVoice informs you clearly and routes actions through **`L1` Official Intents** and **`L3` Shizuku / ADB**.<br>3. For Android 13+ sideloaded APKs, our Permission Wizard gives a 1-tap button to **App Info $\rightarrow$ `⋮` $\rightarrow$ Allow restricted settings**. |
| **3** | **"Unlock the phone when I say my password" vs. `DevicePolicyManager` / OEM Keyguards** | `DevicePolicyManager` (`DeviceAdminReceiver`) can **only LOCK** the screen (`lockNow()`); it has zero API to unlock a PIN/pattern/biometric keyguard. Furthermore, some OEM lock screens mark the PIN pad as `FLAG_SECURE` or block Accessibility touch injection on the keyguard. | **Honest 4-Step Unlock Ladder (`SecurityVaultManager`):**<br>1. Verify your spoken passphrase (salted hash) + on-device speaker voiceprint.<br>2. **Step 1 (`L1`)**: Wake screen (`setTurnScreenOn(true)`, `setShowWhenLocked(true)`) + call `KeyguardManager.requestDismissKeyguard()` (completes immediately if Smart Lock / Extend Unlock is active).<br>3. **Step 2 (`L2`)**: If `OmniAccessibilityService` can see the keyguard PIN digits, swipe up and tap the digits of your Keystore-encrypted PIN.<br>4. **Step 3 (`L3`)**: If `L3` Shizuku/ADB is active, inject `input text <PIN> && input keyevent 66`.<br>5. **Step 4**: If the OEM keyguard blocks both `L2` and `L3`, OmniVoice tells you honestly and guides you to enable **Extend Unlock / Smart Lock** (Trusted Voice/Device/Location). |
| **4** | **"Toggle Wi-Fi, Mobile Data, Airplane Mode, or Hotspot with zero touch on Android 12–17"** | Since Android 10 (`API 29`), `WifiManager.setWifiEnabled()`, Mobile Data toggling, and Airplane Mode toggling are blocked for normal third-party apps. | **Control Ladder (`L3 -> L2 -> L1`):**<br>1. If `WRITE_SECURE_SETTINGS` / Shizuku (`L3`) is granted, toggle silently (`Settings.Global.WIFI_ON`, `svc wifi enable`, `svc data enable`).<br>2. Otherwise (`L2`), open `Settings.Panel.ACTION_INTERNET_CONNECTIVITY` or Quick Settings and use `OmniAccessibilityService` to auto-click the switch, then verify the real radio state via `ConnectivityManager` / `WifiManager`. |
| **5** | **"No NDK and no self-written native code" vs. On-Device Wake-Word, VAD & LLM (`Gemma .litertlm`)** | Many C++ wake-word/LLM repos require compiling JNI/NDK code, which violates the builder constraint, and bundling a 1–2 GB `.litertlm` model inside the APK would break APK build/install limits. | 1. **Zero NDK**: We use only prebuilt Maven artifacts and pure Kotlin/Android platform APIs (`AudioRecord` DSP + VAD + Android 13+ `createOnDeviceSpeechRecognizer` + AICore / LiteRT-LM model manager).<br>2. **Non-Bundled Model Manager**: Large `.litertlm` models are **never** bundled inside the APK; `OnDeviceLlmAndModelManager` checks device RAM/storage (`Tier A/B/C/D`) and lets you download or import a `.litertlm` file from device storage while the 300+ rule-based offline parser works out-of-the-box with 0 MB download. |
| **6** | **Large `assets/vocabulary.json` (3,000+ target) & `assets/commands_dataset.json` (800+ target) vs. Single-Turn File Output Limits** | Generating 3,000+ vocabulary entries and 800+ full JSON command objects in a single tool call would exceed output size limits. | In **Module 4**, we ship structured, high-coverage `vocabulary.json`, `commands_dataset.json`, and `stt_corrections.json` files plus our programmatic `BilingualBenchmarkRunner` (324+ verified commands), and provide a batch-expansion generator so we can append additional batches in subsequent turns until any desired entry count is reached. |
| **7** | **Cloud Environment `build.gradle.kts` Constraints (`compileSdk = 36`, Existing `applicationId` & Signing Configs)** | The AI Studio Android container pre-configures `compileSdk = 36` and existing signing configs in `app/build.gradle.kts`; modifying signing configs or setting an unreleased `compileSdk = 37` when only SDK 36 platform jars are installed in the container would break compilation. | We set **`minSdk = 31`** explicitly as requested, keep `compileSdk = 36` / `targetSdk = 36` (the latest stable SDK installed in the build container) while writing full **Android 17 (`API 37`) forward-compatible checks** in `Android12To17Compat.kt` (using SDK constants and safe reflection for API 37 `AdvancedProtectionManager` and background-audio hardening), and preserve the container's signing config while adding full R8/ProGuard rules in `app/proguard-rules.pro`. |
