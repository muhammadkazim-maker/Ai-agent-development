# Phase 0 (b): Android Non-Root Feasibility Table, Control Ladder & Technical Trade-Offs

This document provides a transparent, engineering-accurate assessment of what Android (`minSdk = 26` through `targetSdk = 36`, Android 8.0 to Android 15/16) allows a non-rooted application to do directly, what requires a **one-time user setup**, what requires **optional ADB / Shizuku privileges**, and what is **strictly blocked by the Android OS** along with the exact honest workaround we implement.

---

## 1. The 4-Tier Control Ladder (`L1 -> L2 -> L3 -> L4`)

Every device action in OmniVoice is executed through our **Control Ladder**, attempting the fastest, cleanest tier first, verifying the real OS state afterward, and automatically falling back to the next tier if blocked:

| Tier | Name | Prerequisites | How It Works |
|---|---|---|---|
| **L1** | **Official Android SDK & System Intents** | Standard runtime permissions (`CALL_PHONE`, `SEND_SMS`, `CAMERA`, `WRITE_SETTINGS`, etc.) | Direct Android framework calls (`TelecomManager`, `SmsManager`, `CameraManager`, `AudioManager`, `AlarmClock`, `ContactsContract`). Fastest (<50 ms) and works even when the screen is off. |
| **L2** | **`OmniAccessibilityService` + `NotificationListenerService` UI Automation** | One-time user enablement in **Settings -> Accessibility -> OmniVoice** (plus *"Allow restricted settings"* on Android 13+ if sideloaded) | Inspects live window trees (`AccessibilityNodeInfo`), clicks buttons (`ACTION_CLICK`), types text/passwords (`ACTION_SET_TEXT` + sensitive clipboard fallback), scrolls lists, gestures (`dispatchGesture`), reads/replies to notifications via `RemoteInput`, and navigates system settings panels (`Settings.Panel.ACTION_INTERNET_CONNECTIVITY`). |
| **L3** | **Privileged Shell / Secure Settings via ADB or Shizuku (Optional)** | One-time PC ADB command (`adb shell pm grant com.aistudio.omnivoice.qkvyma android.permission.WRITE_SECURE_SETTINGS`) or **Shizuku** app authorization | Enables silent background toggling of restricted settings (`Settings.Global` / `Settings.Secure`), automatic recovery if an OEM kills the Accessibility Service (`enabled_accessibility_services`), and direct shell commands (`svc wifi enable`, `svc data enable`, `cmd wifi connect-network <ssid> wpa2 <pass>`) when Shizuku binder is active. |
| **L4** | **Root Shell (`su`) (Optional)** | Rooted device only (Magisk / KernelSU) | Runs `su -c` commands if present; never required or assumed by OmniVoice. |

### 3.3 Root-Cause Analysis of the 3 Audio Bugs & Permanent Fixes (`Section 3`, `F-033`)

1. **Bug #1: `"Recognition error (11)"` (`SpeechRecognizer.ERROR_SERVER_DISCONNECTED`) & Tight Retry Loops**
   - **Root Cause:** Creating or calling `SpeechRecognizer.startListening()` off the main looper thread, or starting a `SpeechRecognizer` while `AudioRecord` / Gemini Live WebSocket already holds the microphone focus, or retrying immediately in `onError()` before the Android system binder releases the previous session.
   - **Permanent Fix:**
     - Enforce a single `AudioPipelineStateMachine` so `SpeechRecognizer` and `AudioRecord` **never** run simultaneously.
     - Always instantiate, start, stop, and destroy `SpeechRecognizer` on `Dispatchers.Main.immediate`.
     - Map all 15 `SpeechRecognizer` error codes to human-readable symbolic names (e.g., `11 -> ERROR_SERVER_DISCONNECTED`) and use exponential backoff (`1000ms -> 2000ms -> 4000ms -> 8000ms`) with automatic engine failover instead of tight retry loops.

2. **Bug #2: Unclear / Robotic / Mispronounced Bilingual Voice**
   - **Root Cause:** Sending raw markdown (`**bold**`, URLs, JSON fragments) or Roman Urdu words directly to an English-only TTS voice, or playing 24 kHz PCM chunks directly to `AudioTrack` without a jitter buffer.
   - **Permanent Fix:**
     - Add a dedicated **24 kHz PCM Jitter Buffer** (`AudioOutputManager`) with smooth frame scheduling and `USAGE_ASSISTANT` / `CONTENT_TYPE_SPEECH` attributes.
     - Build `SpeechNormaliser` that separates `displayText` (shown in UI with Nastaliq/Latin styling) from `speechText` (markdown/URLs stripped, numbers/times expanded in the target language, Roman Urdu transliterated or routed to the clearest bilingual voice).

3. **Bug #3: Ghost Second Voice / Echo in the Background**
   - **Root Cause:** Two audio pipelines running in parallel—e.g., Gemini Live WebSocket playing 24 kHz native audio while its `outputAudioTranscription` or a background `SpeechRecognizer` fallback triggers local `TextToSpeech.speak()` at the same time, OR the microphone picking up the speaker's own output without `AcousticEchoCanceler` / half-duplex gating.
   - **Permanent Fix:**
     - **Single-Modality Output Rule:** `outputAudioTranscription` from Gemini Live is used **exclusively for UI subtitles** and is **never** passed to `TextToSpeech`.
     - **Single `AudioOutputManager` Singleton:** Owns both the `AudioTrack` (for 24 kHz cloud PCM) and the `TextToSpeech` instance (for offline speech). Starting one immediately stops and flushes the other, deduplicated by monotonic `turnId`.
     - **Hardware `AcousticEchoCanceler` + Half-Duplex Barge-In Gate:** Attach `AcousticEchoCanceler.create(audioRecord.audioSessionId)` on `VOICE_COMMUNICATION`; while the assistant is in `SPEAKING` state, normal STT is muted and only high-threshold echo-cancelled barge-in energy (`> bargeInThresholdDb`) can interrupt playback.
